# RAGBot — Codex Build Instructions

Build a lightweight Retrieval-Augmented Generation (RAG) chatbot API in Python.
This is a portfolio project for a software engineering internship application at Roadie.

## What to build

A FastAPI application that lets users upload plain-text or PDF documents and then ask questions about them. Answers are generated by retrieving relevant chunks from a FAISS vector index and passing them as context to an LLM.

## Tech stack

- Python 3.11+
- FastAPI (REST API + async)
- LangChain (document loading, text splitting, retrieval chain)
- FAISS (local vector store, `faiss-cpu`)
- OpenAI API or a local model via `ollama` (configurable via env var)
- SQLite (store document metadata: filename, upload time, chunk count)
- pytest (unit + integration tests)
- Docker + docker-compose (containerized deployment)

## Project structure

```
Dockerfile
docker-compose.yml

README.md
.env.example
```

## MVP endpoints

| Method | Path | Description |
|--------|------|-------------|
| POST | /documents | Upload a .txt or .pdf file, chunk it, embed it, store in FAISS + SQLite |
| GET | /documents | List all indexed documents (filename, chunk count, upload time) |
| POST | /chat | Send a question, retrieve top-k chunks, return LLM answer + sources |
| GET | /health | Liveness check |

## Key implementation details

- Use `RecursiveCharacterTextSplitter` with chunk_size=500, overlap=50
- Embed with `OpenAIEmbeddings` (or `ollama` embeddings if no API key)
- Persist FAISS index to disk (`faiss_index/` dir) and reload on startup
- Return sources (filename + chunk text) alongside every answer
- All config via environment variables using pydantic-settings
- Full pytest suite: mock LLM calls, test chunking, test retrieval
